# Benchmarks

Generated by `cargo bench --bench report` (release profile) with `BENCH_CORPORA` naming the corpora below (see Development in the README), on 12th Gen Intel(R) Core(TM) i5-12450HX, 12 threads, linux, with source files in the OS page cache.
Tokens are estimated at ~4 bytes/token for both the full text and the reduced output.

The benchmark walks up to 200,000 files per corpus, so the whole Linux kernel is searched. The server walks 20,000 by default (`ASTLENS_MAX_FILES`). The cache keeps its default 512 MB budget.

## Startup

Spawn → `initialize` response: **2.7 ms** (median of 10; no indexing at startup).

### Columns

- **Cold parse**: read and tree-sitter-parse every supported file on one thread.
- **Search: cold**: first `search_symbols` on an empty cache (walks the tree, parses in parallel, persists results).
- **Search: warm**: later searches, scored against the symbol names kept in memory (still walks and `stat`s every file).
- **Search: after restart**: new process state with the LMDB store; files are validated by git blob hash instead of re-parsed.
- **Pruned to budget**: `read_file_pruned` output for files that exceed the budget.
- **`read_symbol` / whole file**: tokens for one function/method versus reading its entire file.
- **`find_references`**: identifier tokens named QUERY, definitions included; looked up in the identifier offsets recorded at parse time (warm cache).
- **Word matches dropped**: whole-word text matches that are not references (comments, strings, docs, non-source files).
- **`search_text` regex**: one run of `TODO|FIXME|XXX` over every text file.
